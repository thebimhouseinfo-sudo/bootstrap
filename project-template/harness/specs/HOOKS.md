# Native hooks and portability contract

**Copilot native:** `--runtime copilot` installs `.github/hooks/criteria.json` (Copilot camelCase `sessionStart`, `preToolUse`, `subagentStop`, `userPromptSubmitted`) and `.github/agents/*.agent.md`. A recognized direct edit of Criteria is denied. One-shot staged apply needs an observed `technical-advisor` subagentStop and a LATER Human chat confirmation bound to that session and staged proposal hash. This remains a procedural host/tool-scoped gate, not cryptographic Human identity or universal indirect write protection. Native VS Code hook dispatch remains UNVERIFIED until a real host smoke.


**Continue CLI hooks:** `.continue/settings.json` declares Claude-compatible `PreToolUse`, `SessionStart`, `SubagentStop`, `UserPromptSubmit`, `Stop` (command hooks). `.continue/hooks/criteria-gate.cjs` denies recognized direct Criteria writes with exit code 2 and hookSpecificOutput; `criteria-apply.cjs` gates one-time SHA-bound writes behind observed Advisor/Human events. Native CLI dispatch MUST be tested on the installed `cn` version. **Continue IDE extension** has no verified equivalent interception; `.continue/rules/` are instructions, not enforcement. The CLI's `agent` hook handler is not implemented in the inspected source, so this does not itself summon Advisor. See `.continue/HOOKS_SETUP.md`.

**Generic target host implementation is mandatory during setup when technically supported:** `.generic/ADAPTER_REQUIREMENTS.md` defines what the installing agent must research, write and test for each actual IDE/CLI. Do not confuse the absence of a prebuilt generic adapter with an optional port, nor claim equivalence from copied Python source. A verified native hook may only claim the exact operations actually intercepted.

**Installed for Codex:** `.codex/hooks.json` declares `SessionStart`, `PreToolUse` (exact `apply_patch`), and `Stop`; each calls `harness/codex/hook.py` using the installed Python interpreter (project-root lookup works from nested directories). Hook JSON input/output follows official Codex hook schemas: https://learn.chatgpt.com/docs/hooks

**Runtime trust:** project config and hook definitions must be trusted using Codex `/hooks`; administrative policies can disable hooks. Project-local scripts are not system-enforced controls, and parent sandbox/approval still applies. Never auto-bypass hook trust.

- **SessionStart:** injects bounded contract/status context.
- **PreToolUse:** in Git projects first checks the explicitly configured active development branch from the Git common directory; unknown/frozen/unregistered/detached checkout causes an observed direct apply_patch to be denied. Non-Git projects do not need this Git-only configuration. This hook cannot cover shell/MCP/hosted edits. Then it makes a hash-checked pre-edit snapshot of existing files identified in direct `apply_patch` headers when `hook-policy.json` enables it. Known protected paths receive warning; the hook does not authenticate human decisions. Supported direct `apply_patch` operations may be denied if a requested snapshot fails. Shell commands, hosted tools and many MCP changes can bypass this path: do not claim full file-write protection or a universal sandbox.
- **Stop:** only for a configured `ACTIVE` goal in `harness/active-task.json`. Validate scoped goal/theory/test/evidence links, then run configured `harness/common/checks.json` (no shell). A failed check requests **one** continuation; `stop_hook_active` suppresses further automatic retries. No check config or no approved active task → no fake PASS and no forced continuation. This neither signs G0/G11 nor calls subagents.
- Hook policy fields in `harness/hook-policy.json`: `snapshot_apply_patch`, `stop_verify`. Default enabled for supported paths; activation is conditional on a real active task and approved command list.

**Port to Claude/other CLI/IDE:** reuse Python `common/*.py`; adapt event names, JSON schema, command lookup/trust and supported blocking semantics. If no matching hook, provide a manual runner and label GUIDED_ONLY. Equivalence means measured outcomes, not copying Codex JSON verbatim.

**Evidence required:** allowed/blocked apply_patch, hash-snapshot, Stop PASS/FAIL/NOT_CONFIGURED, trust prompt and actual Codex native invocation on the user’s version; CI Python tests alone do not certify the host.

## Staged bootstrap activation
Explicit first-time `install.py --staged` writes `harness/setup-state.json` phase BOOTSTRAPPING **before copying hooks**. Codex/Claude handlers and Antigravity's setup_hook.py defer blocking ONLY for a valid phase BOOTSTRAPPING state. A missing, malformed, or unknown state MUST NOT turn protections off. Legacy installs with no staged marker retain existing behavior. This is an operational coordination mode, not a host-enforced security boundary. Do not use `--staged` to unlock an existing legacy or READY installation. After configuration audit and disposable smoke tests, collect real fresh-session host observations, obtain explicit human final-lock approval, then ask the Human to run `setup_lifecycle.py activate --evidence harness/setup-live-evidence.json` in an independent interactive terminal; passing `--human-approved` from an agent or CI cannot authorize activation. Re-run live tests AFTER activation and use `setup_lifecycle.py finalize --post-lock-evidence harness/setup-postlock-evidence.json` in a Human-operated terminal. Keep the original setup tab open until successful handoff. The agent cannot authenticate human approval or fake host evidence; independent offline repair remains necessary for broken native hooks.
