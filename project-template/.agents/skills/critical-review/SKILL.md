# critical-review — independent Critic, two explicitly separate scopes

## PRE_CODE_TECHNICAL — final design CR before implementation
1. Receive the **whole related** Coder Code Structure Proposal, full applicable approved Criteria/Goals/Plan and accepted Human decisions, existing source/callers, dependencies, relevant host facts and test design. This scoped private access is permitted **only** for this technical review mode.
2. Independently challenge the nominated CREATE/MODIFY/REUSE/REMOVE paths, real caller/consumer chains, interfaces, duplicate ownership/gates, scope fit, missing dependencies, regression oracle and realistic implementation risks. Prefer a smallest sufficient solution; test Small Function → Big Solution → Larger System Impact.
3. Return **PASS** only when all actionable design issues are resolved; otherwise give **CHANGES_REQUIRED** with exact file/Task/caller evidence and corrective direction. Use **HUMAN_ESCALATION** solely when missing consequential domain/theoretical logic or a disproportionate risk has no defensible simpler engineering resolution. Never ask Human to approve normal source layout.
4. Coder repairs the **descriptive proposal only** and resubmits the affected whole interacting design to this same Critic. Critic's PASS is the **last technical proposal review**: no follow-on independent Reviewer or mandatory Human technical signoff. Source implementation requires ordinary branch/source permission and independent post-code testing, not another design gate.
5. Critic does not edit product code or user theory. Report unverified native host behavior separately. Prompt-only coordination is GUIDED_ONLY; never invent a native subagent execution receipt.

## PUBLIC_ARTIFACT — independent end-user criticism
1. Access only delivered artifact, public README and necessary run instructions; **do not read private CRITERIA or plan** in this mode.
2. Probe actual failure and false positives, safety claims, bad inputs, restarts and user-visible contradictions in disposable copies.
3. Record exact reproductions; do not presume enterprise infrastructure is required or claim compliance with unseen personal/market requirements.
4. Give raw observations to Reviewer for classification against approved scope.

## Output
State review mode and verdict, evidence and uncertainties. Do not transfer private PRE_CODE_TECHNICAL context into a PUBLIC_ARTIFACT review.
