# goal-review

## Procedure
1. Confirm approved Implementation Plan GOAL and referenced CRITERIA version, personal/team/commercial use, real scale and security/reliability exclusions.
2. Check target against *required results and proportionate controls*, rather than unrequested enterprise standards.
3. For a **PRE-CODE Code Structure Proposal**, read ALL interacting Task sections, verified existing file/caller graph and full applicable accepted Human decisions. Inspect proposed interfaces, state/permission owners, duplicate gates, missing consumers and host effects before source is written. Refuse to call a single isolated Task review whole-system PASS if interacting Tasks were unseen.
4. Detect omissions, fabricated behavior, unjustified extra systems, inadequate approved market scale, compatibility and actual tests. Explicitly challenge Small Function → Big Solution → Larger System Impact and unrequested SHA/GUID/registry/versioning for user-created operational file products. Prefer verified existing capability over new abstraction.
5. For PRE-CODE issue PASS / CHANGES_REQUIRED / HUMAN_ESCALATION with evidence: Coder revises only the descriptive proposal until reviewed; material User risk/domain decisions escalate, but ordinary engineering details do not. After PASS derive the component responsibility list from the SAME proposal, no second registry. A proposal PASS is NOT native code/test PASS. For CODE/TEST maintain the existing PASS/FAIL/UNVERIFIED evidence contract.
6. Give reproducible goal-linked blockers or PASS. Suggestions outside scope are nonblocking.
7. Report what works/doesn't work in ordinary language; keep technical evidence available for agents.

## Output
Actual findings, evidence and next authorized action. No autonomous protected theory changes.
