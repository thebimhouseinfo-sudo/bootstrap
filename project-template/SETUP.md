# Bootstrap project setup — runtime-neutral

AI installs from repo root using `python install.py --target PATH --tier Standard --runtime RUNTIME --apply` **after explicitly choosing one of antigravity/codex/claude/continue/generic (generic additionally requires --target-app), preview and user approval**. This copies only missing files; it does not overwrite existing work. A conflicting `AGENTS.md` produces `AGENTS.bootstrap.md` for manual reconciliation, and exit 2 means unresolved conflict.

**Local-only setup:** the installer also manages a marked block at the end of the target `.gitignore`, preserving existing rules. Agent directories, harness/runtime state, local AGENTS/CLAUDE/TASKS, project environment profile, generated trace and report templates stay local. Product source and actual product docs remain trackable. Preview lists `UPDATE .gitignore`; apply atomically updates that managed content. Already tracked setup is reported as `TRACKED_LOCAL_SETUP` with exit 2; ignore rules cannot untrack it. Do not automatically delete files, rewrite history or remove index entries. The canonical `project-template/` in bootstrap remains versioned source.

In Git projects, apply verifies effective ignore behavior before copying setup: nested ignore exceptions produce `LOCAL_SETUP_NOT_IGNORED` and exit 2. Fix those rules before retrying. Git access/index errors block rather than pretending the repository is absent. If Git is unavailable or the project has not been initialized, rerun after `git init` to validate real ignore behavior.

- **GENERIC READY / copy as-is:** Codex and Google Antigravity IDE have been installed and tested by the Human as ready-to-use generic coding-agent setups. Choose the runtime/tier and copy the template without rewriting generic role/skill/script files.
- **CONFIGURED, HOST-UNTESTED:** Claude Code has prepared native role/skill files, settings and Python hook adapter; the Human has not been able to test on Claude Code. Continue has role configs/rules nearly ready; select actual provider/models and verify Continue's VS Code integration before making host-specific claims.

This generic mode does NOT silently install native roles. Reuse shared template and port only native adapters/registration details per platform documentation. The purpose is to save setup tokens/quota and avoid re-creating the entire harness.
- **PROJECT-SPECIFIC CONFIGURATION IS STILL REQUIRED EVEN WHEN GENERIC READY:** CRITERIA, verified host/stack/API, working paths, actual build/test commands in `harness/common/checks.json`, Git active/frozen branch choice and optional domain knowledge. Keep approved plans/tasks project-specific. Do not confuse generic agent usability with a product-specific setup being complete.

## Google Antigravity IDE setup
Install with `python install.py --target PATH --tier Standard --runtime antigravity --apply` (run `python install.py --ask-first` separately for a one-batch questions-only block). The installer configures native `.agents/hooks.json` (Stop lifecycle hook dispatching to `harness/common/verify.py`), `.antigravity/agents/*.md` (role definitions with model assignments and Gemini 3.8 Flash High fallback), and native `.agents/skills/`.

**After install:** open the workspace in Google Antigravity IDE. Roles, skills, and hooks are loaded natively. Run `python harness/common/status.py --tier Standard --runtime antigravity` to inspect inventory and readiness; configure `harness/common/checks.json` with verified project build/test commands.

## Codex setup
Install with `--runtime codex`. Inspect `/hooks` inside Codex and trust the exact definitions if approved. Configure actual project commands in `harness/common/checks.json` and an explicitly approved `harness/active-task.json`; no fabricated goal ID. Stop checks activate for configured tasks only.

## Claude Code setup
Install with `--runtime claude`. The installer copies `.claude/settings.json` (with `UserPromptSubmit`, `PreToolUse`, `Stop` hooks), `.claude/agents/*.md` subagent files, and `harness/claude/hook.py` (the Python adapter). The adapter reuses `harness/common/*.py` and reads native `hook_event_name` from JSON stdin; exit 2 blocks supported events. Hook commands locate the adapter from project root or nested directories.

**After install:** open the project in Claude Code, check that the hook fires on prompt submit (context message appears). Run `python harness/common/status.py --tier Standard --runtime claude`; configure `harness/common/checks.json` with real build/test commands; set branch authority if using Git. Save real host/client/version, exact source hashes and observed hook/block/Stop evidence. Do not clear readiness blockers by editing capability labels; Standard engines remain NOT_CONFIGURED until implemented and verified.

After installation, all target projects still need project-specific CRITERIA, host/stack/SDK, build/test commands and relevant Git/model/knowledge configuration. This generic READY label is separate from `RUNTIME_VERIFIED`, authenticated approvals and `ENFORCED` protections. Installer copy/CI tests alone do not prove those stronger properties.

## One-batch installer intake

Run `python install.py --ask-first` to **display all questions as one noninteractive block** for the AI to ask in chat. This command NEVER changes files and cannot be combined with `--apply`. After Human answers once, pass explicit `--target`, `--tier`, `--runtime` and, if generic, `--target-app`. Run a preview without `--apply`; only after Human approves it, rerun with `--apply`. The installer does not ask step-by-step questions in a terminal; host command execution permission dialogs remain separate from chat configuration questions.
