# Bootstrap project setup — reuse first

AI installs from repo root using `python install.py --target PATH --tier Standard --runtime codex --apply` **after preview and user approval**. This copies only missing files; it does not overwrite existing work. A conflicting `AGENTS.md` produces `AGENTS.bootstrap.md` for manual reconciliation, and exit 2 means unresolved conflict.

- **READY / copy as-is:** generic agents, skill procedures, native Codex/Claude role and Claude skill configurations, shared contracts, Codex baseline scripts.
- **CONFIGURE only for actual project facts:** CRITERIA, profile, approved plan/tasks, verified build/check commands in `harness/common/checks.json`, optional skill/knowledge. Never invent facts.
- **If user plan/model access differs:** Codex `.codex/MODEL_SELECTION.md`; Claude `.claude/MODEL_SELECTION.md`; Continue `.continue/README.md` (provider-dependent setup). **Main chat model is always user-selected**. Do not rewrite generic roles or consult these model guides when presets work.
- **Runtime capability limits:** native Codex hook JSON, and the Claude Code native adapter (`harness/claude/hook.py` + `.claude/settings.json`), scoped Python snapshot/restore and bounded Stop/verify are shipped and SCRIPT_TESTED, but real host hook trust is UNVERIFIED for both. Authenticated approvals, signed gates, complete trace/stale propagation and automated role orchestration remain NOT_CONFIGURED. `harness/common/inventory.py --tier TIER --runtime RUNTIME` checks inventory only; `harness/common/verify.py` checks configured commands, not real-host acceptance.

For approved theory changes, discuss and settle delta with human **without editing CRITERIA**.
- **Technical Advisor as human consultant, never Reviewer/CR:** advise on the **full initial CRITERIA draft** before first approval; or on **approved CRITERIA plus human-settled delta** only after the human asks to apply and **before editing**. Requirements come from CRITERIA; optionally examine actual architecture/environment and limited source when required to estimate feasibility, costs, prerequisites and rework. No Plan/Code review, no PASS/FAIL, no coding or veto. Tạm dùng / Ổn / Nâng cao is an optional useful comparison, not mandatory. Human decides; Planner applies only authorized scope.

- **Discovery:** empty project starts with Planner brainstorm/research and OPEN entries in CRITERIA, not invented development tasks. Approved theory stays in CRITERIA only.
- **Active Git branch (all tiers):** before planning or coding in a Git repository, Human selects the current active development branch and frozen branches; `python harness/common/branch_authority.py configure --active v5 --freeze main --remote origin` previews, then `--apply` records locally after Human authorization. ## Claude Code setup
Install with `--runtime claude`. The installer copies `.claude/settings.json` (with `UserPromptSubmit`, `PreToolUse`, `Stop` hooks), `.claude/agents/*.md` subagent files, and `harness/claude/hook.py` (the Python adapter). The adapter reuses `harness/common/*.py` and is invoked via `CLAUDE_HOOK_EVENT` env var + JSON stdin; exit 2 blocks the operation.

**After install:** open the project in Claude Code, check that the hook fires on prompt submit (context message appears). Run `python harness/common/status.py --tier Standard --runtime claude`; configure `harness/common/checks.json` with real build/test commands; set branch authority if using Git. Update `harness/common/capabilities.json` → `runtime_smoke.claude` to `RUNTIME_VERIFIED` only after observing real hook dispatch, block behavior and a Stop verification cycle on the installed Claude Code version.
